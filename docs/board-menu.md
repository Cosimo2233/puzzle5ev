# AXU5EV-P 板端菜单与验收

当前电机与磁铁接线使用单个 M0 USB 桥接，见 [M0 接入](m0-bridge.md)；
以下早期“两路 USB 串口”验收项应按桥接两通道分别检查，不能打开同一 tty 两次。

仓库示例配置为 `board=axu5ev`、`plan_only=true`、`motion_enabled=false`、`physical_buttons=false`。实际板端已按用户授权设置 `plan_only=false`、`motion_enabled=true`，沿用测试成功的机械标定；键鼠确认后，必须通过完整识别、求解与执行检查才搬运。开机只显示菜单。本轮提速自动验证始终使用只求解入口。

菜单配置在 `/opt/ec26e/config/axu5ev/menu.json`，硬件环境在 `/opt/ec26e/config/axu5ev/machine.env`。部署源文件在 `deploy/axu5ev/`。启动脚本要求名为 `ec26e-hdmi` 的 framebuffer；出厂 PS DisplayPort 不视为 HDMI OUT 验收。

## 鼠标与画面

左侧可直接点击固定/随机模式，下方为开始、预览、取消按钮。菜单显示箭头光标，按钮显示手形；任务开始或相机释放期间禁用重复开始，取消仍可用。键盘 M / Enter / P / Esc 保留。

实时画面和轮廓分析分别刷新，轮廓只在画面未移动且结果足够新时叠加。预览不卡住菜单切换；正式任务仍须六张不同新帧、至少两秒和原有稳定阈值。

点击开始后，先显示本次稳定采图；完整方案通过检查后，用相同颜色标注源碎片 S、预测位置 T、移动方向和次序，并在左侧显示最终拼合图及旋转角。预测是本次采图快照，不跟随运动过程实时更新。没有有效解、任务失败或切换模式时清除旧预测。该显示功能不改变既有开始按钮的运动权限。

专用 HDMI 屏幕关闭 Xorg 屏保和 DPMS，避免空闲十分钟后黑屏；菜单开机自启保留。

## 已具备与待办

- 板端独立 Python 3.11、中文菜单和四片预览已验证，用户已确认显示器实际出图。
- DMA 分割与两个几何核已通过实际比对。提速版本使用 PL 图像预处理、固定/随机批量配准，四凸片间隙核仅用于固定模式，详见 [PL 提速说明](pl-speed.md)。
- 新 PL 与出厂设备树地址冲突。已部署受恢复开关控制的工程启动镜像选择和 SysV 菜单自启，原始启动文件保留。
- 摄像头连续采集已通过，热重启后的 USB3 枚举仍有不稳定现象。M0 桥接运动和原机械标定已由用户通过固定四片实测；随机实物样品与提速后现场验收待补。
- 2026-10-20 修复 HDMI 辅助复位极性接线后，用户已确认彩条/文字颜色正常、中文菜单正常。新版 PL 的图像与几何测试也已通过。整板断电后直接启动候选 v1，摄像头恢复；实际菜单预览已连续更新 50 帧，所存状态识别到 4 个拼块。热重启仍可能丢失 USB3 Hub，见 [增量联调记录](validation/axu5ev-migration-20261020/peripheral-bringup.md)。

## 更换接线或平台后的验收顺序

1. 接 HDMI OUT、UVC 摄像头和两个 USB 串口模块，运行 `probe_board.py` 保存枚举信息。
2. 按实际 USB 序列号或物理端口建立 `/dev/ec26e-camera`、`/dev/ec26e-xyz-uart`、`/dev/ec26e-rotation-uart`；出厂系统 `/dev/video0` 是 MIPI，候选平台停用 MIPI 后摄像头可能成为 `/dev/video0`，始终使用核验过的别名。
3. 验证摄像头格式/帧率、持续采集；校准新相机视角、颜色阈值和像素到机械坐标，旧参考角点不可直接复用。
4. 验证 HDMI 的 RGB 颜色、1280×720 时序、连续刷新和菜单键鼠交互。
5. 在仅规划模式下测试固定/随机任务及无相机、无解、取消等分支。
6. 验证 PL DMA 正常/超时/取消、帧号及 CPU/PL 结果一致性，再测包含传输的端到端耗时。
7. 最后按真实接线核对 M0 桥接 XYZ/旋转通道身份和协议。自动验证只求解，实际搬运由用户手动启动。

每次记录软件版本、bit/HWH 哈希、启动配置与输入。构建通过和设备节点存在都不等价于真实硬件验收。
