# M0 锁存故障、预览提示与收尾 Z 下降

日期：2026-10-23。板卡时钟落后，以下原日志时间保留板卡值。

## 本次任务为什么失败

生产日志 `menu-ec247e57-1f82-449f-8854-dd64123dbfb8.log` 中，
09:01:20 与 09:01:36 两次固定四片均通过识别、求解与运动规划检查；
点击到完整方案分别约 7.455、5.086 秒，invalid_frames=0。
失败位于共享 M0 会话的只读启动检查，STATUS 都为
`armed=false, magnet=false, fault=2, version=1, malformed=0`。
尚未发送 ARM 或运动数据；“磁铁初始化失败”是接口初始化的包装错误，
不能据此认定磁铁损坏。后续“磁铁会话未打开”是清理阶段的附带错误。

`fault=2` 为 UART 接收错误/溢出的汇总代码，一次瞬时错误也会锁存。
30 次后续只读 STATUS 均保留该错误；当时未收到主动下游回包。
旧固件没有分路历史数据，无法反推出是哪路 UART 或哪种错误。

## M0 更新与边界

已备份原 128 KiB Flash，5072 字节旧固件与 TX-only 已部署版本完全一致，
没有退回早期 XYZ 接收固件。新增只读 DIAGNOSTICS：逐 UART 记录硬件
overrun、break、parity、framing、软件队列满、首次/最近时间及 armed 下次数。
查询不清故障、不续期；ARM/DISARM 也不抹掉这些累计诊断数据。

诊断固件已通过 J-Link 100 kHz 烧录并读回校验，BIN 5536 字节，SHA-256：
`2f99374af0ced686ea04f05a2138f1658c5c5013157bf54181c700c56c4bcca7`。
桥接仓库提交 `8b124fa`；旧 TX-only 构建保留用于回滚。

板端连续 101 次查询、30 次串口重新打开，共 131 份诊断全部 fault=0、
armed=false、magnet=false、malformed=0，三路错误计数均为零。
固件重启会清除旧锁存状态；此结果**不是原始干扰根因已查清或根治的证据**。
生产应用遇到启动故障时会追加 `M0_UART_DIAGNOSTICS` 明细，查询失败仍
保留最初 STATUS，不自动解除保护或重发运动指令。

用户随后于板卡 09:17:42 手动启动固定四片，09:18:36 日志报告完成搬运、
返回 XY 起点并正常失能退出。此任务由用户启动，使用尚未改动收尾 Z 的版本；
仅凭日志不能验收实际拼合精度。

## 摄像头停止提示

刷写与 UART 验证期间，维护进程持有正式任务锁。用户三次打开预览都因
TaskBusyError 退出，旧菜单却无条件把预览进程退出写成“请检查 USB 接线”。
占用已释放；此次错误不能归因于摄像头损坏。

新增有界错误消息管道，区分资源占用、实际采集错误和普通进程退出。
正常关闭不再报 USB 错误；错误消息不会成为图像帧。资源占用时显示
“设备正由其他任务或维护占用，请稍后重新打开预览”。

## 正常结束时放下 Z

按用户新要求，固定与随机共用执行器均在旋转归零、Z 抬起的 XY 回程及
原有抬升位提示结束后，确认 XY 已到软件起点、关闭磁铁，再下降 Z。
沿用实机 `MOTION_Z_DOWN_DEGREES=0`、`Z_UP=90`、每段等待 1 秒，
不更改机械标定、速度或串口。完成状态要求 XY 为起点且 Z 为下降位置，
下降等待结束后才失能。取消、回程失败或收尾下降失败不报告 FINISH，
不重试移动或补做下降。

该收尾位置与现有 `MOTION_Z_BOOT_DEGREES=0` 一致。旧版已完成的任务仍
可能停在抬升位置；下一次实际启动前需要恢复约定的下降起始位置。
