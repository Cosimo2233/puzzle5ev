# 启动前 1°、任务内后续吸取前 2°（2026-10-30）

用户报告连续两次拼兔子中途停止。当前启动日志 `menu-c5c159a7-4af2-494b-9e79-6511dbe4d8f7.log` 显示，两次分别在第五片、第四片搬运指令完成后，于下一片吸取前报错：目标 0°、反馈 358.7°、误差 1.3°。两次都已通过视觉、七片规划及软件限位，底层回零位置等待通过；应用的逐片 1° 复核使任务退出。故障时下一片尚未下降或通磁吸取。

此前取消了搬运中的额外 1° 复核，但把“运动前保留”实现为每片吸取前仍按 1° 检查，没有覆盖用户希望整次任务持续完成的情况。本次按用户最新明确要求修正共享执行器 `sw/src/ec_26_e/tasks/task1/actuation.py`：

- 启动回零及第一片吸取前，容差仍为 1°。
- 第一片放置后，后续各片吸取前的零位容差为 2°，恰好 2° 允许继续。
- 仍用单圈最短角差计算，358.7° 对零位的误差为 1.3°，不再导致上述中止。
- 不增加携带碎片期间的角度复核；底层多圈位置等待、通信/协议故障、超时、取消及异常清理保持。
- 运行中零位超过 2° 或反馈为 NaN 等无效值时，仍会在下一片吸取前拒绝；不承诺发生任意故障也绝不停机。

`_require_rotation_angle` 默认容差为 1°，后续周期通过 `pick_positioned=True` 显式使用 2°，第一周期不放宽。这是共享运动执行器的规则，固定、随机和七巧板模式共用；未修改原机械标定、图案、视觉或桥接协议。
