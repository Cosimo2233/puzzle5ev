# 七巧板字体修复与手动试机启用（2026-10-27）

用户报告“七板”及图案下拉名称缺字。板端实际使用的 `wqy-microhei-ui.ttf` 是原界面裁剪字体，缺少“巧、猫、兔、鱼、船”等新增字符；展开的 Combobox 列表使用独立的 TkTextFont，也未继承输入框字体。Fontconfig 中的 Noto OTF 无法直接供本板 Tk 的 X11 核心字体路径使用。

修复字体生成脚本：除 ASCII 和应用源码之外，加入独立求解器公共 `PATTERN_NAMES` 中的名称，不复制求解器源码。Poetry 开发依赖新增 fontTools，保留原 WQY 字体和授权来源。下拉输入框与展开列表显式使用同一中文字体，限制列表显示六项，并压缩结果图例末行以避免七片信息被裁切。

## 验证和部署

- 重新生成的字体含全部六个图案名称及“七巧板”字形，覆盖检查无缺字。
- 相关应用、菜单、运动分派模拟和预览测试共 46 项通过，Poetry 配置检查通过。
- 板端完整展开六项，文字和每项边界均正常，见 [截图](picker-expanded.png) 和 [列表检查](picker-result.json)。
- 发布位于 `/opt/ec26e/releases/tangram-font-20261027`。安装器备份原应用、求解器、任务配置和字体，更新后重启 Xorg/菜单，未重载 PL、未改启动镜像。

## 手动运动权限

字体修复核对完成后，按用户本轮明确要求将生产 `tasks/tangram.json` 的 `motion_verified` 设为 true，供用户点击“开始拼图”试机。默认模板仍为 false。单张采图、原有接线、机械标定、XY/Z/旋转参数和原菜单权限均保持原值，修改前后哈希见 [授权与配置记录](manual-motion-enabled.json)。

已用替代进程启动函数检查实际菜单分派：七巧板生成 `--execute` 和 `EC_MOTION_ENABLED=true`，核对过程中没有启动任务或发送运动命令。设备保留在菜单空闲状态，由用户手动选择图案并开始。此开关表示用户授权试机，不表示先前的实物搬运失败已解决或物理精度已经验收。

字体/软件回滚可使用该发布目录的安装器 `--apply --rollback`，恢复其 `production-before` 中的包、任务配置及旧字体；恢复前应确认没有任务或预览运行。
